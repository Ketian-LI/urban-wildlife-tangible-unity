# Scope Freeze V1

更新日期：2026-09-11

冻结状态：P0 技术闭环与 Vertical Slice 的第一版范围已锁定。任何范围变更都必须写入开发日志，并说明替换或删除的内容。

## 项目目标

完成一个实体桌面与 Unity 2D 相连的可研究原型。玩家承担城市公园规划与管理任务，通过 Token 与彩色路径配置空间条件，在人类通行、动物可达性和有限资源之间作出取舍；系统让人类 NPC 与动物自主响应，并通过 Trace 呈现累积后果。

## P0 MVP

### 实物端

- 使用 60 × 90 cm 黑色磁吸板，90 cm 横向、60 cm 纵向平放在桌面。
- 黑色板面直接作为地图底图，不铺整张覆盖层；固定地点使用局部低黏度哑光可移除贴膜标示。
- 摄像头固定在板面正上方，镜头尽量与板面垂直。
- P0 默认使用 DJI Pocket 3 作为主摄像头，并保留 iPhone 13 作为备用。
- 使用独立落地式支架完成固定俯拍，地图板保持在桌面操作。
- 四角校准采用固定的 ArUco `DICT_4X4_50` Marker，安装在独立硬卡或薄板上并以磁吸固定，不粘贴到地图板且不可由玩家移动。
- P0 Token 最终主体采用3–4 mm浅色桦木夹板，不使用顶部视觉贴纸；木件制作前先完成等比例纸板轮廓验证。
- Food Hotspot Token 采用最大外径60 mm的柔和六边形桦木主体，以铺装纹样表达城市广场或人类活动节点。
- Food Hotspot 使用一个10 × 7 mm方向缺口及8 × 5 mm的A/B轮廓编码槽，输出逻辑ID 10–12。
- Woodland 允许使用哑光布面表达区域，但必须保留中央刚性轮廓编码木座作为机器视觉输入。
- Woodland 中央识别木座采用直径50 mm、厚3–4 mm的圆形桦木片，外层不规则毛毡最大宽度约120 mm。
- Woodland 中央木座使用相同方向缺口及C、A+C编码槽，输出逻辑ID 20–21；软件不读取会变形的毛毡外轮廓。
- Woodland 布面采用四角磁吸底座保持平整；P0 不识别布面形状变化。
- Woodland 四个毛毡锚点分别使用约 15 × 15 mm 薄塑料底座承托 10 × 10 mm 方形磁吸片，磁吸面朝下与板面接触。
- P0 实体输入仅制作 3 个 Food Hotspot Token 和 2 个 Woodland Token；Bench、Human Activity、Bin 和 Management Sign 只预留接口。
- 四角安装固定的白底校准 Marker，用于识别边界、方向和透视校正。
- 使用可移动的 Food Hotspot 与 Woodland 临时 Token，以及一条约 15 mm 宽、100 cm 有效长度的高饱和哑光罗纹带表示 Planned Human Path；首选亮洋红色，并用青色和橙色小样完成实拍对照后锁色。
- 路径带使用可移动的薄磁吸点在入口、广场、出口和主要转弯处保持平整。
- P0 阶段允许使用纸板轮廓、独立打印校准卡和现成磁铁，不要求最终木制工艺。

### 视觉识别端

- 软件基线使用 Python 3.12.10、opencv-contrib-python 4.14.0.94 和 NumPy 2.4.6，并在项目 `.venv` 中安装。
- 通过圆片轮廓及边缘缺口识别玩家 Token 的逻辑ID、位置和角度；ArUco 仅负责四角校准。
- 完成彩色路径的 HSV 分割、去噪与 Path Mask 输出。
- 根据四角校准 Marker 完成 Camera 到 Game 的坐标标准化。
- 首轮采集基线为 1920 × 1080、30 fps；Confirm 后等待画面稳定约 1 秒再生成布局数据。

### Unity 端

- Unity 项目固定使用本机已安装的 6000.3.4f1；开发期间不跨 Unity 大版本升级。
- 单张 2D 公园地图。
- 地图下方设置一个约 18 × 12 cm 的固定不规则池塘，中心距左 50 cm、距上 42 cm；它是不可移动的地图障碍，不占用 Token 数量。
- Food Availability Hotspot 与 Woodland 两类核心条件；Food Hotspot 表示人类活动形成的食物可获得性，不表示直接控制或投喂动物。
- 玩家界面把 `food_hotspot` 表述为长椅、广场等“人类活动节点”；内部字段名暂时保留，以兼容已经通过验证的轮廓识别和数据包。
- Unity显示层用活动节点环区分Food Hotspot、用叶片/冠层/木芯区分Woodland，并在入口A和出口B显示双门柱；这些装饰不改变Token占地、ID或约束判定。
- 实体路径继续使用洋红色带识别；进入Unity后，同一中心线显示为带土肩、石质路缘和碎石细节的写实砂砾公园步道。输出材质不反向影响HSV或路径约束。
- Walker、Dweller 或 Visitor 等基础人类行为。
- 三类人物统一使用高角度斜俯视正脸显示；该变化只改善地图尺寸下的人物可读性，不改变摄像机、路线或行为规则。
- 人物采用自然成年人体型，并与鸽子、松鼠、狐狸保持接近真实的相对大小；显示缩放与行为参数相互独立。
- 鸽子、松鼠和狐狸三种动物的基础状态机。
- 三轮使用可读的群体规模而非每种动物各1只：第1轮7只鸽子、3只松鼠、1只狐狸；第2轮9/4/1；第3轮8/3/2。数量是交互原型参数，不代表真实生态密度。
- 松鼠和狐狸在地图尺寸下必须保持可辨轮廓：松鼠宽圆且尾巴侧弯，狐狸细长且直尾带明显白尾尖。
- 人类通行检查：入口与必要人类活动目标之间保持连续可达路径。
- 动物可达性检查：Woodland 到 Food Hotspot 至少存在一条可达路线，并以人流密度作为干扰成本。

### 系统闭环与研究记录

- 实体布局能够通过标准数据包传入 Unity。
- P0 在 Confirm 后通过原子写入的 JSON 文件把布局传给 Unity，并按周期归档。
- 每轮包含不同的规划情境、预算或改动次数限制；三轮依次为公园修复、周末野餐压力和黄昏最终提案。
- 完成 Brief、Plan、Constraint Check、Confirm、Predict、Run、Observe、Re-plan 的完整单周期；Predict 是 Confirm 内的必要动作，不增加新的技术阶段枚举。
- Predict 至少记录“预计哪一物种进食最多”与“预计压力出现在哪里”；Observe 对比进食与回避结果并提供下一轮可检验的解释，不输出总分。
- 跨周期使用可见的滚动记忆：记录上一轮人类行程、分物种进食、回避、各物种成功使用最多的活动节点和松鼠平均熟悉度；下一轮回访与谨慎行为读取这些数据，Reset Session时全部清空。
- 若某物种上一轮成功进食，下一轮至少一半该物种代理优先回访同一逻辑ID的活动节点；松鼠熟悉度保留80%，松鼠与狐狸的响应距离按上一轮每次回避增加2%，最高增加25%。这些是可预测试的游戏参数，不是动物学习模型。
- 输出最小可用的研究日志，包含轮次情境、预测、动物数量及分物种行为汇总。

### P0 第一张规划任务

- 名称：周末公园重新规划。
- 固定地点：入口 A 和出口 B 分别为左右边缘中央的 6 × 8 cm 圆角区域，中心距上均为 30 cm；中央广场为 20 × 14 cm 横向椭圆，中心位于距左 45 cm、距上 18 cm 处。
- 固定障碍：池塘为约 18 × 12 cm 不规则横向区域，中心位于距左 50 cm、距上 42 cm；规划人类路径、松鼠和狐狸不能穿越，鸽子可以飞越但不能在池塘中落脚或觅食。
- 人类目标：一条不自交的连续路径按入口 A、广场、出口 B 的顺序连接三个地点。
- 动物目标：至少一个 Woodland 能通过相对低干扰的路线到达 Food Hotspot。
- 空间限制：Food Hotspot 边缘距路径边缘至少 1 cm，不得与池塘重叠，并须完整位于板面内。
- 来源限制：Food Hotspot 必须位于中央广场内，或其中心距规划路径中心线不超过 10 cm；数值作为预测试基线。
- 操作限制：每周期最多调整 3 个逻辑元素；任一 Token 计 1，路径整体几何变化计 1，路径磁吸锚点不单独计数。
- 初始条件：由主持人按场景预设基准布局摆放 Token 与路径，玩家从该布局开始规划。
- 校准安全：四角各有 8 × 8 cm 不可遮挡区域。
- 交互方式：屏幕 Confirm Layout 按钮为主、空格键为快捷键；P0 不制作实体按钮。
- 预测试节奏：Plan 不倒计时、Run 60 秒、Observe 约 30 秒，每个 Session 3 个周期。
- 每轮进入 Run 前必须完成两项预测；预测会在下一轮 Plan 开始时重置，但已写入研究日志。
- 观察结果：人群拥堵、动物觅食，以及人类与动物路线的交叉位置。
- 确认反馈：只显示人类路径连续、动物至少一路可达、Food Hotspot 来源有效和改动次数；动物具体路线与干扰结果留到 Run 和 Trace。

P0 验收：玩家在磁吸板上移动 Food Hotspot、Woodland Token 和彩绳后，系统能够识别布局、检查人类与动物通行约束并传入 Unity，使数字公园中的人类与三种动物产生可观察的变化。系统呈现取舍，不输出唯一正确答案或总分。

## P1 Final Target

- Bench、Human Activity、Bin 与 Management Sign。
- Human Trace、Animal Trace 与 Combined Trace。
- 刺猬作为第 4 物种。
- 6 至 8 个系统事件。
- Session Summary、声音和视觉完善。

P1 功能只在 P0 技术闭环和 Vertical Slice 稳定后进入开发。

## 明确不做

- 不制作真实伦敦公园的精确生态预测模型。
- 不制作以唯一正确答案或总分为目标的教育软件。
- 不允许玩家直接拖拽、生成或控制动物。
- 不在 MVP 阶段制作多地图、联网、多玩家或复杂 3D 内容。
- 不在核心循环稳定前增加新物种、事件或装饰系统。

## Scope 变更规则

1. 新功能必须说明它支持哪一个研究问题或验收目标。
2. 若硬里程碑延期超过 3 天，优先删除 P1 功能。
3. 每次删减或调整都记录在开发日志中，作为 Research Through Design 的过程证据。
4. 2026-10-25 后不增加核心功能，只修复严重问题和可理解性问题。
